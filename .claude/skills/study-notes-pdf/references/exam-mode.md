# Exam alignment (when the user provides a sample exam or past paper)

1. Read the exam first and list its question types and their weight:
   MCQ, True/False, fill in the blank, short answer ("Why…", "How…",
   "What is the function of…", "Differentiate between…"), applied scenarios.
2. Map every exam question to the lesson it came from. Lessons that are
   heavily examined get more cards; topics the exam asks about but the
   source barely covers get an accuracy note.
3. Keep the notes as notes. Add Q&A as an extra layer, not a replacement:
   - after each lesson section, a `.card.qa` with 3-8 likely questions in
     the exam's own style;
   - answers are short keyword answers (one line, highlighted terms), the way
     a student would write them under time pressure;
   - every "Differentiate between" style question gets a `.card.vs`.
4. For MCQ / True-False, list the classic traps (pink highlight): absolute
   words, swapped pairs, numbers that are close to each other.
5. If an exam question is ambiguous or its expected answer contradicts the
   source, say so in a small note instead of silently picking one.
